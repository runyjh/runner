# 러너 올인원

택배 영업점 러너의 기사 관리·배차·정산 올인원 프로그램입니다.

| 무엇 | 어디에 |
| --- | --- |
| 프로그램 코드 (화면, 서버) | **이 GitHub 저장소** |
| 백엔드 데이터 (기사 정보, 로그인 기록) | 구글 드라이브의 `러너 올인원 DB` 시트 |
| 기사 서류 사진 | 구글 드라이브의 `기사 서류` 폴더 |
| 암호화 키 | Apps Script 스크립트 속성 (저장소에 없음) |

저장소의 `main` 브랜치에 코드가 올라오면 GitHub Actions가 **문법 검사 → Apps Script에 올리기 → 웹앱 새 버전 배포**를 자동으로 합니다. 기사용 앱 주소(URL)는 바뀌지 않습니다.

## 폴더 구성

| 경로 | 내용 |
| --- | --- |
| `src/Code.gs` | 서버 코드 (구글 시트·드라이브 입출력, 시트 직접 수정 처리, 암호화, 로그인) |
| `src/Settle.gs` | 정산관리 서버 코드 (쿠팡 정산서 반영, 기사별 정산 계산, 명세서, 입금목록, 마감) |
| `src/SettleMigrate.gs` | 기존 정산 시트(러너_쿠팡정산관리_2026) → 정산 DB 이관 (한 번만 쓰는 기능) |
| `src/Index.html` | 기사용 화면 (로그인, 회원가입, 비밀번호 찾기·변경) |
| `src/Admin.html` | 관리자 화면 (기사 정보관리, 기사스케줄, 노선관리, 정산관리, 업무스케줄, 배번호 관리, 공지사항, 계정관리·서류 4종 인쇄 양식) — 웹앱 주소 뒤에 `?page=admin` |
| `src/appsscript.json` | Apps Script 설정 (서울 시간대, 웹앱 공개 범위) |
| `scripts/check.js` | 배포 전 문법 검사 |
| `.github/workflows/deploy.yml` | 자동 배포 설정 |
| `.github/workflows/pages.yml` | 깃허브 페이지(배너 없는 기사 앱·관리자 화면) 자동 배포 |
| `scripts/build-pages.js` | `src/` 화면 파일로 깃허브 페이지용 화면을 만듦 (웹앱 주소·앱 아이콘을 넣음) |
| `site/` | 깃허브 페이지에만 쓰는 파일 (앱 아이콘, 설치 정보 manifest, 오프라인 안내 sw.js) |

## 처음 한 번만 하는 설정

### 1. Apps Script 프로젝트 만들기

1. 러너 업무용 구글 계정으로 [script.google.com](https://script.google.com) → **새 프로젝트** → 이름을 `러너 올인원`으로 바꿉니다. 코드는 붙여넣지 않습니다.
2. 왼쪽 **⚙ 프로젝트 설정** → **스크립트 ID**를 복사해 둡니다. → `SCRIPT_ID`
3. [script.google.com/home/usersettings](https://script.google.com/home/usersettings) 에서 **Google Apps Script API** 를 **사용**으로 바꿉니다. (자동 배포에 필요)

### 2. 자동 배포용 인증 정보 만들기

PC에 [Node.js](https://nodejs.org) (LTS)를 설치한 뒤, 터미널(윈도우는 명령 프롬프트)에서 실행합니다.

```
npx @google/clasp@2.4.2 login
```

브라우저가 열리면 1번과 **같은 구글 계정**으로 로그인하고 허용합니다. 그러면 아래 파일이 생깁니다.

- 윈도우: `C:\Users\사용자이름\.clasprc.json`
- 맥: `/Users/사용자이름/.clasprc.json`

이 파일을 메모장으로 열어 **내용 전체**를 복사해 둡니다. → `CLASPRC_JSON`
이 내용은 구글 계정 열쇠와 같으니 다른 곳에 붙여넣거나 공유하지 마세요.

> PC에 설치하기 어렵다면 GitHub 저장소의 **Code → Codespaces → Create codespace** 로 연 터미널에서
> `npx @google/clasp@2.4.2 login --no-localhost` 를 실행해도 됩니다.

### 3. GitHub Secrets 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 등록합니다.

| 이름 | 값 |
| --- | --- |
| `SCRIPT_ID` | 1번에서 복사한 스크립트 ID |
| `CLASPRC_JSON` | 2번에서 복사한 `.clasprc.json` 내용 전체 |
| `DEPLOYMENT_ID` | 6번에서 등록 (지금은 비워 둠) |

### 4. 첫 코드 올리기

저장소 **Actions → Apps Script 배포 → Run workflow** 를 누릅니다. 1~2분 뒤 초록색 체크가 뜨면 성공입니다. (DEPLOYMENT_ID 가 없다는 노란 경고는 정상입니다.)
Apps Script 편집기를 새로고침하면 `Code.gs`, `Index.html` 이 들어와 있습니다.

### 5. setup 실행 (DB 만들기)

1. 편집기에서 함수 선택 칸을 **`setup`** 으로 바꾸고 **▶ 실행**합니다.
2. **권한 검토** → 계정 선택 → "확인하지 않은 앱" 경고에서 **고급 → 러너 올인원(으)로 이동 → 허용**. 본인이 만든 스크립트라 나오는 정상 경고입니다.
3. 로그에 `설정 완료. DB: https://...` 가 나오면 드라이브에 `러너 올인원 데이터` 폴더, `러너 올인원 DB` 시트, `기사 서류` 폴더가 생긴 것입니다.

### 6. 웹앱 첫 배포

1. 편집기 오른쪽 위 **배포 → 새 배포** → 톱니바퀴 → **웹 앱**
2. 다음 사용자 인증 정보로 실행: **나** / 액세스 권한: **모든 사용자** → **배포**
3. 나오는 **웹 앱 URL** 이 기사용 앱 주소입니다.
4. 같은 화면의 **배포 ID** 를 복사해 GitHub Secret `DEPLOYMENT_ID` 로 등록합니다.

이제부터는 코드가 바뀔 때마다 이 배포가 자동으로 새 버전이 됩니다.

## 깃허브 페이지로 열기 (상단 구글 배너 없애기)

script.google.com 주소로 열면 구글이 맨 위에 "이 애플리케이션은 Google Apps Script 사용자가 만들었습니다" 배너를 강제로 붙입니다.
화면을 깃허브 페이지(`https://아이디.github.io/저장소이름/`)에서 열면 배너가 없고, **홈 화면에 앱으로 설치**(러너 아이콘, 주소창 없는 전체 화면)도 됩니다.
데이터는 지금처럼 구글 시트·드라이브에만 있고, 화면은 웹앱 주소로 요청을 보내 Code.gs 가 처리합니다 (같은 코드·같은 속도).

**처음 한 번만**

1. `Code.gs` 를 이번 버전으로 올리고 **웹앱을 새 버전으로 배포**합니다 (새로 생긴 `doPost` 입구가 있어야 함). 배포 설정은 그대로: 실행 = 나, 액세스 = 모든 사용자.
2. 웹앱 주소(`https://script.google.com/macros/s/…/exec`)를 복사합니다. 편집기 → 배포 → 배포 관리에서 볼 수 있습니다.
3. 깃허브 저장소 **Settings → Secrets and variables → Actions → Variables** 탭 → **New repository variable**
   - Name: `RUNNER_API_URL` / Value: 위 웹앱 주소
4. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
   - 무료 계정은 저장소가 **공개(Public)** 여야 페이지가 만들어집니다. 화면 코드만 보이고, 비밀번호·암호화 키·데이터는 구글 쪽에만 있어 안전합니다.
5. **Actions → 깃허브 페이지 배포 → Run workflow** 를 한 번 누릅니다. 초록 체크가 뜨면 주소가 표시됩니다.
   - 기사 앱: `https://아이디.github.io/저장소이름/`
   - 관리자: `https://아이디.github.io/저장소이름/admin/`
6. 휴대폰에서 기사 앱 주소로 로그인까지 되는지 확인합니다.
7. 확인이 끝나면 앱스크립트 **프로젝트 설정 → 스크립트 속성**에 `PAGES_URL` = 기사 앱 주소 를 추가합니다.
   이후 예전 script.google.com 주소로 들어온 기사님은 "새 주소로 열기" 안내 화면을 보게 됩니다. (예전 화면이 필요하면 주소 뒤에 `?stay=1`)

**관리자 앱 설치**: 관리자 주소(`…/admin/`)로 로그인하면 왼쪽 아래 **📲 관리자 앱 설치** 버튼이 보입니다.
PC 크롬·엣지는 누르면 설치 창이 떠서 바탕화면·시작 메뉴에 **러너 관리자**(노란 '관리자' 표시 아이콘)가 생기고, 아이폰·아이패드는 사파리 '공유 → 홈 화면에 추가' 안내가 나옵니다.
기사 앱과 아이콘·이름이 달라 둘 다 설치해도 헷갈리지 않습니다.

**PC 설치 파일 (윈도우 10/11)**: `site/download/Runner_Setup.bat` (깃허브 페이지 주소 `…/runner/download/Runner_Setup.bat`).
더블클릭 → 1 관리자 / 2 기사 앱 / 3 둘 다 / 4 지우기 를 고르면 바탕화면·시작 메뉴에 러너 아이콘이 생기고, 엣지(없으면 크롬)로 주소창 없는 앱 창이 열립니다.
처음 실행할 때 파란 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**. 관리자 화면에서 PC로 '관리자 앱 설치'를 눌러도 이 파일을 받을 수 있습니다.

**기사님 설치**: 새 주소로 로그인하면 홈에 **📲 홈 화면에 러너 앱 설치** 버튼이 보입니다.
안드로이드는 누르면 바로 설치 창이 뜨고, 아이폰은 사파리 '공유 → 홈 화면에 추가' 안내가 나옵니다. 카카오톡에서 열었으면 '다른 브라우저로 열기' 안내가 나옵니다.

**동작 방식·주의**
- 화면은 `Content-Type: text/plain` 으로 `{"fn":"api_login","args":[…]}` 를 보내고, `doPost` 가 그 함수 결과를 JSON 으로 돌려줍니다.
- 부를 수 있는 함수는 이름이 `api_` / `adm_` 로 시작하는 것뿐입니다 (`setup` 등 관리 함수는 밖에서 못 부름).
- 구글이 바쁠 때 오는 오류 화면, 60초 넘는 무응답은 "연결이 원활하지 않습니다" 안내로 처리합니다.
- 웹앱을 **새 배포(새 주소)** 로 만들면 `RUNNER_API_URL` 도 바꿔야 합니다. 자동 배포(deploy.yml)는 같은 배포 ID에 새 버전을 올리므로 주소가 바뀌지 않습니다.
- 화면(html)을 고치면 deploy.yml(구글)과 pages.yml(깃허브 페이지)이 함께 돌아 두 주소 모두 최신이 됩니다.

## 코드를 고칠 때

1. GitHub에서 `src/` 의 파일을 고치고 `main` 에 커밋합니다. (웹에서 연필 아이콘으로 바로 고쳐도 됩니다)
2. **Actions** 탭에서 진행을 확인합니다. 문법 오류가 있으면 빨간 X 로 멈추고 배포하지 않습니다.
3. 초록 체크가 뜨면 기사용 앱에 반영된 것입니다. 휴대폰에서 새로고침해 확인하세요.
4. 릴리스 안내에 "setup 다시 실행"이 있으면 편집기에서 `setup` 을 한 번 실행합니다. 기존 데이터는 지워지지 않습니다.

**Apps Script 편집기에서 코드를 직접 고치지 마세요.** 다음 자동 배포 때 저장소 내용으로 덮어써집니다.

## 관리자 화면

주소: **웹앱 URL 뒤에 `?page=admin`** 을 붙입니다.
예) `https://script.google.com/macros/s/…/exec?page=admin`

### 첫 관리자 만들기

1. 새 코드가 배포된 뒤 편집기에서 **`setup`** 을 한 번 실행합니다. DB 시트에 `admins`(관리자 계정), `admin_log`(관리자 작업 기록) 탭이 생깁니다.
2. `admins` 탭 2행에 **아이디**, **이름**, **비밀번호 재설정**(영문+숫자 8자 이상)을 입력합니다.
3. 잠시 뒤 관리자ID·생성일시가 채워지고 비밀번호 칸이 비워지면 완료입니다. 위 주소로 로그인합니다.

관리자를 더 추가할 때도 같은 방법입니다. 관리자를 막으려면 **상태**를 `정지` 로 바꿉니다.

### 기사 정보관리에서 할 수 있는 것

| 기능 | 방법 |
| --- | --- |
| 상태별 보기 | 위쪽 탭(전체/승인대기/승인/반려/정지). 승인대기가 있으면 그 탭이 먼저 열림 |
| 기사구분별 보기 | 둘째 줄 탭(고정/백업/품앗이/외부용차). 구분이 비어 있는 기사는 **구분 미지정** 탭 |
| 검색 | 이름, 기사코드, 아이디, 연락처, 차량, 캠프, 라우트 |
| 새 기사 등록 | 오른쪽 위 **+ 새 기사 등록** → 이름과 기사구분만 필수, 나머지는 나중에 채워도 됨. 바로 **승인** 상태로 등록 |
| 배정 캠프 · 라우트 | 상세(또는 새 기사 등록)의 **배정 캠프 · 라우트** 에서 노선관리에 등록된 캠프를 고른 뒤, 숫자(구분1)마다 **A·B·C·D** 를 한 글자씩 눌러 고름 (**전체** = 그 숫자의 글자 모두). 예: 404 의 D + 405 의 A·B → `404D,405AB`. 노선관리에서 중지된 글자는 흐리게. 일부 회전만 맡으면 회전(D1·D2·F3) 체크 해제. 백업 기사는 **백업**, 용차는 **용차**. 저장하면 기사의 소속캠프·기본노선이 되어 기사스케줄(미입차 계산, 빈칸 자동 채우기)에 그대로 쓰입니다. 기사스케줄의 스케줄 설정 창도 같은 방식 |
| 기사구분·기사코드 | 상세 맨 위에서 고정/백업/품앗이/외부용차 버튼, 기사코드 입력. **자동**을 누르면 같은 구분의 가장 큰 번호 다음 번호를 제안 (예: B007 → B008) |
| 가입 승인·반려·정지 | 기사 줄을 눌러 상세 → 상태 버튼 → 저장 |
| 정보 수정 | 상세에서 고친 뒤 저장. 바뀐 칸은 주황색으로 표시 |
| 주민번호·면허번호·계좌번호 | **전체 보기**(30초 뒤 다시 가림), **변경**(새 번호 전체 입력) |
| 서류 확인 | 서류 칸의 **보기** → 화면에서 바로 사진/PDF 확인 |
| 임시 비밀번호 | 상세 맨 아래 **임시 비밀번호 지정** → 기사는 다음 로그인 때 직접 변경 |
| 선택한 기사 삭제 | 목록 왼쪽 체크박스로 여러 명 선택 (맨 위 체크박스 = 지금 보이는 기사 모두) → **선택한 기사 삭제** → `3명 삭제` 처럼 표시된 문구를 그대로 입력해야 삭제됨. 처리 내용은 한 명 삭제와 같음 |
| 기사 삭제 | 상세 맨 아래 **기사 삭제** → 기사 이름을 그대로 입력해야 삭제됨. 앱 로그인은 바로 끊기고, 가입 서류 폴더는 드라이브 휴지통으로 (30일 안 복구 가능). 배번호 신청서 등 기록은 남음. 잠시 쉬는 기사는 삭제 대신 **정지** 권장 |

- 기사코드는 기사마다 겹칠 수 없습니다 (영문은 자동 대문자).
- 외부용차처럼 앱을 쓰지 않는 기사는 쿠팡플렉스 아이디 없이 등록할 수 있습니다 (목록에 **앱 미사용** 표시). 나중에 앱을 쓰게 되면 아이디를 넣고 **임시 비밀번호 지정**을 하면 됩니다.
- 등록할 때 쿠팡플렉스 아이디와 **앱 임시 비밀번호**를 같이 넣으면, 기사님은 그 비밀번호로 바로 로그인한 뒤 새 비밀번호를 정합니다.
- 상세를 연 뒤 시트나 다른 관리자가 같은 기사를 먼저 고쳤다면, 저장할 때 "새로고침 후 다시 수정해 주세요"라고 막습니다. 덮어쓰기를 방지합니다.
- 개인정보 **전체 보기**, **서류 보기**, **정보 수정**, **임시 비밀번호 지정**, **기사 등록·삭제**는 `admin_log` 탭에 누가 언제 했는지 자동으로 기록됩니다.
- 시트에서 직접 고치는 방법도 그대로 쓸 수 있습니다. 관리자 화면에서 **새로고침**을 누르면 시트 내용이 반영됩니다.

### 정산관리 (쿠팡 정산 → 기사 정산 · 명세서 · 입금)

정산기간은 **전월 26일 ~ 당월 25일 = 당월 정산** 입니다 (예: 2026-10 정산 = 2026-09-26 ~ 2026-10-25). 금액은 쿠팡 정산서가 공급가, 기사 단가·지급은 모두 부가세 포함입니다.

**어디서 읽나**
- 기사·노선·단가 = 러너 올인원 DB (기사 정보관리 / 노선관리) 에서만, 근무일수 = 기사스케줄(스케줄 DB) 에서만 읽습니다.
- 쿠팡 정산서 원천·분실·차수이력, 공제·가불·용차, 정산 설정은 별도 파일 **`러너 올인원 정산 DB`** (`러너 올인원 데이터` 폴더, 스크립트 속성 `STL_DB_ID`) 에 탭별로 저장되며 시트에서 직접 고쳐도 됩니다.
- 올린 쿠팡 엑셀 원본은 드라이브 `러너 올인원 데이터/쿠팡 정산서` 폴더에 `2026-10_2차.xlsx` 처럼 저장됩니다.

**순서**
1. **쿠팡 정산서 올리기**: 쿠팡 정산 엑셀(.xlsx)을 고르면 브라우저에서 바로 읽어 정산월·차수를 제안합니다 (원천 시트 = ID·배송건수·총금액 열이 있는 시트, 분실 시트 = ID·차감금액 열). [반영]하면 그 정산월의 이전 차수는 이 파일로 바뀌고 ID별 금액 변동은 `stl_rounds` 에 남습니다.
2. **기사별 정산**: 기사 목록·합계·확인 필요(미등록 쿠팡 ID, 단가 미입력, 노선 미등록, 계좌·사업자번호 미입력, 실입금 마이너스, 가불 미상계 …). 기사를 누르면 **정산서(급여내역서)** — 요약·노선별·일자별·용차/분실·세금계산서 안내 — 를 보고 **인쇄 · PDF** 할 수 있습니다.
3. **공제·가감 / 가불금 / 용차** 를 입력 → 바로 다시 계산됩니다.
4. **입금목록**: 기사 계좌번호 전체 표시(관리자 기록에 남음), 입금체크·입금일·메모, **대량이체용 복사**(은행·계좌·예금주·금액).
5. **이 달 마감**: 결과를 고정합니다 (그 달 쿠팡 정산서·공제·용차 수정 불가, 입금체크는 가능). 마감 해제하면 지금 데이터로 다시 계산.

**계산 규칙 (기존 정산 시트와 같음)**
- 쿠팡 매출 = (총금액 + 프레시백) × 1.1
- **정산의 기준은 쿠팡 아이디** (불변). 메인 아이디 + 서브 아이디 = 정산서 하나, 정산금·세금계산서·입금은 메인 아이디의 **명의자** 1명에게. 단가 구분은 **기사 정보관리의 기사구분이 최우선** (메인 아이디), 서브 아이디만 아이디 관리의 단가 구분이 우선. **아이디 관리 ↔ 기사 정보관리 연동**: 기사 정보관리에서 기사를 만들거나 쿠팡플렉스 아이디·이름을 바꾸면 아이디 관리에 자동 반영되고, 아이디 관리에서 아이디를 추가·변경하면 없는 명의자는 기사 정보관리에 자동 등록되고(메인 아이디는 쿠팡플렉스 아이디로), 메인 아이디의 단가 구분은 기사구분에 반영됩니다. 한 아이디로 다른 기사가 일한 날은 **아이디 사용 기록**(정산관리 → 아이디 관리 → 사용 기록)에 적으면, 그 기간에 그 아이디로 잡힌 배송·프레시백·미계약·프로모션·분실파손이 **일한 기사 본인 정산으로 자동으로** 옮겨집니다 (단가도 그 기사 아이디 기준). 명세서에는 일한 기사 쪽에 `아이디 (명의자 아이디) 사용분`, 명의자 쪽에 `○○ 사용분 이전` 이 보입니다. 일한 기사에게 본인 정산 아이디가 없으면 명의자에게 남기고 '확인 필요'에 띄웁니다.
- 배송 단가: ① 아이디 정산 방식 `용차내역` → 0 (용차 표 금액으로 지급) ② 그 날 그 아이디로 일한 기사(아이디 사용 기록, 없으면 명의자)의 **일시단가**(기간·노선이 맞을 때) ③ `원청단가` → 쿠팡 단가 × 1.1 (10원 반올림, 대표·운영자용) ④ 노선관리 구분별 단가 중 **아이디의 단가 구분** (고정 = 기사단가, 백업 = 백업단가, 품앗이 = 품앗이단가, 외부용차 = 외부단가. 비우면 명의자의 기사구분)
- 프백 가중치(추가인센티브) = 건당 × 1.1 (.5 내림) × 지급률 / 프레시백 = 회수 인센티브 × 지급률 − 기사 **프레시백 차감**(13% 는 100원 반올림, 금액은 그대로 → 러너 몫)
- 미계약 라우트 = 금액 × 1.1 × (1 − 수수료율) / 기타(프로모션·소급) = × 지급률 / 분실파손 = 차감금액 × 1.1 (10원 반올림) 기사 부담
- 세금계산서 = 지급 합계 − 분실 − 계산서 차감 항목 · 공급가 = ÷ 1.1
- 산재·고용(기사 공제) = 공급가 × (1 − 경비율) × 요율 (10원 미만 버림, 월 보수 80만원 미만 고용 제외). 경비율·요율은 캠프별 산식을 기사 지급액 비중으로 안분, 빈 칸은 기본값. 공단 실납부는 항상 기본값 × 2(러너 50%) 로 계산해 차이를 러너 몫으로 표시합니다.
- 실입금 = 세금계산서 − 산재 − 고용 − 입금 차감(가불금 상환·기타 공제·퇴사 보류금) + 입금 가산(보류금 반환)
- 용차: 우리 기사가 대신 뛰면 (용차 단가 × 건수 − 그 기사 노선 단가 × 건수) 만 추가 지급 / 차액부담 기사는 (용차 금액 ÷ 건수 − 기준단가, 반올림) × 건수 를 계산서에서 차감
- 자동 항목: 정기 수당·공제(기간 안 매달), 목표 매출 수당(연 목표 ÷ 12 − 수당 뺀 계산서, 단위 버림), 동일인 매출 분할(원 기사 실수령이 목표 이상인 범위에서 최대 이전), 퇴사 보류금(퇴사월 차감 → 다음 달 반환)

**아이디 관리** (정산관리 → 아이디 관리, 정산 DB `stl_ids` — 시트에서 직접 고쳐도 됨)

| 열 | 내용 |
| --- | --- |
| 쿠팡ID · 구분 · 메인 아이디 | 아이디 한 줄 = 하나. 서브는 메인 아이디 칸에 메인 쿠팡ID → 메인 아이디 정산서로 합쳐짐 |
| 명의자 | 정산금·세금계산서를 받는 기사 (메인 아이디의 명의자가 받음) |
| 단가 구분 | 고정 / 백업 / 품앗이 / 외부용차 (아이디마다) |
| 정산 방식 | 비우면 구분별 단가 / `원청단가` (대표·운영자) / `용차내역` (용차업체: 용차 표 금액으로 지급) |
| 산재·고용 제외 · 프레시백 차감 · 상태 | `Y` 면 보험 공제 안 함 / `13%` 또는 금액 (메인 아이디) / 사용·중지 |

- 쿠팡 정산서를 올릴 때 처음 보는 아이디는 자동으로 추가됩니다 (쿠팡플렉스 아이디가 같은 기사가 있으면 그 기사가 명의자). 명의자가 없으면 "확인 필요"에 뜹니다.
- **아이디 사용 기록** (`stl_usage`): 한 아이디로 여러 기사가 일할 때 "이 기간 이 아이디로 일한 기사". 정산금은 명의자에게 가고, 일시단가·근무일수·명세서의 "일한 기사"에 쓰입니다.
- **일시단가** (정산관리 → 일시단가, `stl_tmp`): 기사 + 시작일·종료일 + 단가 (+ 적용 노선, 비우면 전체, `708C` 또는 `시흥2|708C` 쉼표로 여러 개). 그 기사가 일한 날의 배송에만 적용. (노선관리의 일시단가 칸은 없앴습니다)
- **명의자 사업자 정보**: 사업자등록번호·상호·계산서 이메일은 러너 올인원 DB `drivers` 탭 (아이디 관리 → 명의자 사업자 정보).
- 공제·가감·가불·용차·정기 수당 등은 **정산 아이디**(명의자 이름 또는 쿠팡ID)로 입력하고, 시트에는 `정산 아이디` 칸에 메인 쿠팡ID 가 저장됩니다.

**정산 DB 탭** (`러너 올인원 정산 DB`)

| 탭 | 내용 |
| --- | --- |
| `stl_ids` / `stl_usage` / `stl_tmp` | 아이디 관리 / 아이디 사용 기록 / 기사 일시단가 |
| `stl_raw` / `stl_loss` | 쿠팡 정산서 원천 / 분실파손 (정산월마다 마지막 차수만) |
| `stl_rounds` | 차수이력 (ID별 쿠팡 금액, 직전 차수, 변동액) |
| `stl_adjust` / `stl_advance` / `stl_yongcha` | 공제·가감 / 가불금 원장 / 용차내역 |
| `stl_items` / `stl_config` / `stl_camps` / `stl_kinds` | 명세서 항목 / 지급률·보험·일정 / 캠프별 산재·고용 / 쿠팡 구분값 → 분류 |
| `stl_regular` / `stl_target` / `stl_split` / `stl_leave` | 정기 수당·공제 / 목표 매출 수당 / 동일인 매출 분할 / 퇴사 보류금 |
| `stl_pay` | 입금체크·입금일·메모 |
| `stl_close` / `stl_closed` | 마감한 달 / 마감 때 고정한 결과 (손으로 고치지 마세요) |

**기존 정산 시트 가져오기** (정산 설정 → 기존 정산 시트 가져오기, 한 번만): 기존 `러너_쿠팡정산관리_2026` 시트의 쿠팡 원천·분실·차수이력, 공제·가불·용차, 설정을 정산 DB 로 옮기고, 기사마스터(한 줄 = 쿠팡 아이디)는 **아이디 관리**(메인/서브·명의자·단가 구분·정산 방식·보험 제외·프백 차감)와 **일시단가**로 옮기고, 명의자의 계좌·사업자 정보는 **기사 정보의 빈 칸만**, 노선단가는 **노선관리 구분별 단가의 빈 칸만** 채웁니다. 명의자가 러너 올인원 DB 에 없으면 상태 '정지' 기사로 새로 만들고, 러너 DB 에서 그 아이디를 쓰는 기사가 명의자와 다르면 **아이디 사용 기록**으로 남깁니다. **미리보기**로 먼저 확인하고, 가져온 뒤에는 기존 시트 조회월(DB계산)과 기사별 실입금을 비교한 표가 나옵니다.

### 업무스케줄 (관리자 전용 날짜별 메모)

관리자 화면 왼쪽 메뉴 **업무스케줄**을 누릅니다. 처음 쓰기 전에 편집기에서 `setup` 을 한 번 실행하면 DB 시트에 `work_memo` 탭이 생깁니다.

| 기능 | 방법 |
| --- | --- |
| 날짜 고르기 | 달력에서 날짜를 누름. **‹ ›** 로 달 이동, **오늘** 로 이번 달 |
| 메모 추가 | 오른쪽에 시간(선택)과 내용을 쓰고 **추가** (Ctrl+Enter). 날짜 칸을 바꾸면 다른 날짜에 바로 추가 |
| 완료 | 메모 앞 체크박스. 달력에는 줄이 그어져 보임 |
| 수정·날짜 옮기기 | **수정** → 날짜·시간·내용 변경 → 저장 |
| 삭제 | **삭제** |
| 밀린 일 확인 | 지난 날짜에 완료 안 된 메모가 있으면 위쪽 빨간 줄에 건수가 나오고, **보기**를 누르면 가장 오래된 날짜로 이동 |

`work_memo` 시트에서 직접 줄을 추가·수정·삭제해도 됩니다. 날짜와 내용만 쓰면 메모ID와 작성일시가 자동으로 채워지고, 날짜는 `2026.11.3` 처럼 써도 `2026-11-03` 으로 맞춰집니다. 완료 칸에는 `Y` 를 넣습니다. 관리자 화면에서 **새로고침**을 누르면 반영됩니다.

### 배번호 관리 ('배' 번호판 허가 신청)

처음 쓰기 전에 편집기에서 `setup` 을 한 번 실행하면 DB 시트에 `bib_applications`(신청서), `company`(회사 고정 정보) 탭이 생기고, `drivers` 에 **차량번호** 열이 추가됩니다.

1. **회사 정보 확인**: 배번호 관리 → **회사 정보**. 택배서비스사업자, 영업점, 대표자, 관할법원 등이 서류에 그대로 들어갑니다. (`company` 탭에서도 수정 가능)
2. **새 신청서**: **새 신청서** → 기사 선택. 신청일·계약기간(오늘부터 1년)·관리 방법(자동 증명)이 기본으로 채워지고, 같은 기사의 지난 신청서가 있으면 연료·형태·경력도 가져옵니다.
3. **빈 항목 채우기**: 상세 맨 위 빨간 상자에 서류에 비어 있는 항목이 나옵니다. 신청 정보(경력기간, 연료, 형태, 차량번호 등)는 이 화면에서, 기사 정보(주민번호, 면허, 차명 등)는 **기사 정보 수정하러 가기**로 채웁니다.
4. **서류 인쇄**: 저장 후 **서류 인쇄**(또는 **미리보기**). 4종을 A4로 한 번에 인쇄하며, 필요한 서류만 골라 인쇄할 수도 있습니다. 상태가 `작성` → `출력` 으로 바뀝니다. 서명·날인은 인쇄 후 직접 합니다.
5. **진행 관리**: **제출 완료** → 허가가 나면 **허가 처리**에 '배' 번호판 차량번호 입력 (기사 정보의 차량번호도 이 번호로 바뀜). 반려되면 **반려 처리**에 사유를 남기고, **다시 작성으로** 고쳐서 다시 인쇄합니다.

- 빈 항목이 있어도 확인 후 빈칸으로 인쇄할 수 있습니다 (손으로 채울 때).
- 인쇄할 때마다 그 내용이 암호화되어 신청서에 보관되고, `admin_log` 에 출력 기록이 남습니다.
- 서류 문구가 바뀌면 `src/Admin.html` 의 "배번호 서류 4종 인쇄 양식" 부분 글자만 고치면 됩니다.
- 휴대폰에서 인쇄가 안 되면 **미리보기**로 연 뒤 브라우저 메뉴의 인쇄(PDF 저장)를 쓰세요. 팝업이 막혀 있으면 허용해 주세요.

### 기사스케줄 (배차 · 2주 표)

기존 운영시트의 **스케쥴** 탭과 **백업** 탭을 합친 기능입니다.

스케줄 데이터는 기사·노선 DB 와 **따로**, 별도 파일 **`러너 올인원 스케줄 DB`** (`러너 올인원 데이터` 폴더) 의 `schedule` 탭에 저장됩니다. 기사스케줄를 처음 열 때 자동으로 만들어집니다 (기사 1줄 × 날짜 1칸, 올해 1월 1일 ~ 내년 12월 31일. 그 밖의 날짜로 가면 자동으로 늘어남).
- 예전 버전에서 `러너 올인원 DB` 안에 `schedule` 탭이 이미 있었다면, 처음 열 때 새 파일로 옮기고 원래 탭은 `schedule(이전됨)` 으로 이름만 바꿔 둡니다. 새 파일에 잘 들어간 것을 확인한 뒤 지워도 됩니다.
- 파일 ID 는 스크립트 속성 `SCH_DB_ID` 에 저장됩니다. 이 값을 지우면 다음에 기사스케줄를 열 때 빈 스케줄 DB 를 새로 만듭니다 (예: 해가 바뀌어 새 파일로 시작하고 싶을 때. 이전 파일은 드라이브에 그대로 남음).
- 스케줄 DB 파일에서 직접 고쳐도 바로 화면에 반영됩니다 (편집 트리거가 자동 설치됨).

**데이터 출처**
- **캠프**: 노선관리의 캠프 (캠프 필터·캠프 칸·회전 모두). 노선관리에서 캠프 이름을 바꾸면 스케줄에도 바로 새 이름이 나오고, 캠프를 지우면 그 기사는 '캠프 미배정'으로 보입니다.
- **이름·아이디·기본노선**: 기사 정보관리의 기사 정보에서 자동으로. 승인된 기사는 따로 추가하지 않아도 표에 나옵니다.

**표 보기**
- 위쪽 **2주 / 한 달** 으로 보기를 바꿉니다 (마지막에 쓴 보기를 기억).
  - **2주**: 일요일부터 14칸. 앞 7일은 **확정 · 변경 불가**, 뒤 7일은 **예상 · 변동 있음**. **◀ 이전주 / 이번 주 / 다음주 ▶**
  - **한 달**: 기준을 고릅니다 — **달력 (1일~말일)** 또는 **정산 (전월 26일~당월 25일, 예: 11월분 = 10/26~11/25)**. **◀ 이전달 / 이번 달 / 다음달 ▶**. 매주 일요일 앞에 굵은 선. 출근일수·미입차·백업 명단·중복도 그 한 달 전체로 계산됩니다.
- 날짜마다 ISO 주차, 1~7일은 **Peak물량**, 공휴일 이름 표시.
- **PDD**: 오늘 기준 **내일** 날짜 열을 파란색으로 강조하고 날짜 옆에 `PDD` 표시 (2주·한 달 보기 모두).
- **어드민 업로드 테이블**: 운영시트 메뉴 '어드민: 업로드 테이블 생성'과 같은 결과를 만듭니다 (운영시트 2026-10-25판 스크립트를 그대로 옮김, 실제 운영시트 결과와 줄·순서까지 일치 확인).
  - 대상: 보고 있는 2주 중 **내일(PDD)부터**. 줄 모양: 업무일 / 사업자등록번호(company 탭 '영업점 사업자번호') / 캠프명 / WAVE1 / 아이디 / 출근 / 회전 / 업무라우트 / 비고(미입차 회전) / (빈칸) / 명단.
  - 칸 해석: 출근 → 기본노선, `강서1 527B` → 다른 캠프, `(D1,D2)` → 회전, `(아이디) 업무등록`·`추가업무등록 아이디 노선` → 그 아이디로, 파란 줄 = 업무·업무등록·선탑·신규.
  - 미입차(캠프·회전별 노선 묶음)와 중복(같은 날·캠프·노선·회전 2명 이상)도 따로 만듭니다.
  - 화면에서 탭별로 보고 **이 표 복사**(업무일~비고 9칸, '명단 열 포함' 체크 시 11칸)로 업로드 엑셀에 붙여넣습니다.
  - 같은 내용이 스케줄 DB 파일의 **어드민 업로드** 탭에 운영시트와 같은 배치(왼쪽: 1주차·검은 줄·2주차·미입차 / 오른쪽: 중복·미입차, 색상 동일)로 매번 새로 써집니다. 시트에서 직접 고쳐도 됩니다.
- 날짜 칸으로 아무 날짜 검색 (한 달 보기에서는 그 날짜가 속한 달), 캠프·이름 검색.
- 줄 순서: 캠프 → 고정 → 품앗이 → 백업 → 외부용차 → 표 순서 → 이름. 승인된 기사만 나오고, **정지·대기 기사도 보기**를 켜면 나머지도 보입니다.
- 칸 색은 운영시트 드롭다운과 같습니다 (출근·휴무·병가·미입차·용차·노선변경). 업무등록은 민트, 다른 캠프 노선(예: `안양1 724ABCD`)은 노랑.

**입력**
- 칸을 누르고 바로 타이핑 (또는 두 번 클릭 / Enter). 아래에 추천 목록 (출근·휴무 등, 그 캠프 노선, 이번 2주에 쓴 값, 다른 캠프 노선). Enter 저장 후 아래 칸으로, Tab 오른쪽, Alt+Enter 줄바꿈, Esc 취소.
- 드래그 / Shift+클릭으로 여러 칸 선택 → Delete 지우기, **Ctrl+C / Ctrl+V 로 엑셀·구글시트와 그대로 주고받기** (한 칸을 복사해 여러 칸에 붙이면 모두 채움). Ctrl+Z 되돌리기.
- 고치면 1초 안에 자동 저장 (오른쪽 위 **모두 저장됨**). 다른 관리자가 먼저 바꾼 칸은 덮어쓰지 않고 최신 값으로 바꿔 알려 줍니다.
- 칸에 쓰는 글자는 운영시트와 같습니다: `출근`, `휴무`, `고정휴무`, `527B (D1,D2) [B01]`, `안양1 724ABCD`, `723D,116C (dasom1125) 업무등록` 등.
- **빈칸 자동 채우기**: 지금 보이는 기간(2주 또는 한 달)에서 고정·품앗이 기사의 오늘 이후 빈칸을 고정휴무 요일이면 `고정휴무`, 아니면 `출근`으로 (고정휴무일을 `목,금`처럼 요일로 적은 기사만).
- **기사 줄 순서 바꾸기**: 기사 이름 칸에 마우스를 올리면 나오는 **▲ ▼** 로 같은 캠프 안에서 한 칸씩 위·아래로 옮깁니다. 잠시 뒤 자동 저장되며, drivers 탭 `스케줄 순서` 열(1, 2, 3…)에 들어갑니다. 시트에서 그 열 숫자를 직접 고쳐도 됩니다. 순서가 없는 기사는 구분(고정→품앗이→백업→외부용차)·이름 순으로 그 아래에 붙습니다.
- **+ 비고 줄**: 날짜별 메모 줄 추가. 줄 이름을 누르면 이름 바꾸기·삭제.
- **비고 ↔ 업무스케줄 연동**: 비고 줄 칸의 내용은 실제로 `work_memo` 탭(업무스케줄)에 저장됩니다. 비고 칸에 쓰면 그 날짜의 업무스케줄 메모가 되고, 업무스케줄에서 **비고 줄**(예: `유정훈 비고`)을 골라 추가한 메모는 기사스케줄의 그 비고 칸에 나타납니다. 시간이 있으면 `09:00 내용`, 완료면 끝에 `✓`.
  - 한 칸에 메모가 여럿이면 줄바꿈으로 함께 보이고, 기사스케줄에서 그 칸을 고치면 하나로 합쳐집니다. 칸을 비우면 그 메모들이 삭제됩니다.
  - 예전에 스케줄 시트 비고 칸에 직접 써 둔 글은 처음 열 때 자동으로 업무스케줄로 옮겨집니다 (작성자 `기사스케줄 비고`). 이런 비고 메모는 '지난 미완료' 수에 넣지 않습니다.
  - 비고 줄 이름을 바꾸면 연결된 메모의 줄 이름도 같이 바뀌고, 줄을 삭제하면 메모는 첫 번째 비고 줄로 옮겨집니다.
- 기사 이름을 누르면 **스케줄 설정**: 소속 캠프·라우트(노선관리에서 고르기, 기사 정보관리의 배정 캠프·라우트와 같은 값), 고정휴무일(요일 버튼), 추가휴무, 근무형태, 메모(서브 아이디 등), 표 순서.

**자동 계산 (운영시트 스크립트와 같은 규칙, 실제 운영시트 11/1~11/14 데이터로 결과가 같음을 확인)**
- **출근일수**: 빈칸·휴무·용차·병가·퇴사·미입차·업무등록·휴가를 뺀 칸 수.
- **미입차**: 기본노선이 있는데 그날 아무도 안 들어간 노선, 회전(D1·D2·F3) 일부만 찬 노선, `미입차`라고 적은 칸. 빨간 글씨.
- **백업 명단**: 백업·용차 기사의 칸에서 캠프별로 누가 어느 노선에 들어가는지.
- **중복**: 같은 날 같은 캠프·노선·회전에 두 명 이상 → 주황 테두리 + 중복 줄.
- 회전은 노선관리의 캠프 정보 **기본 회전**을 씁니다 (서초1처럼 D1,D2만 쓰는 캠프는 거기서 바꿈).

**기사 앱**: 홈의 **스케줄**을 누르면 기사님 본인의 이번 주(확정)·다음 주(예상) 일정이 보입니다 (읽기 전용).
날짜마다 **내 캠프에 들어오는 백업**(예: `강서1 백업 527B 김영환`)이 함께 표시되며, 기사스케줄의 '백업 명단'과 같은 규칙으로 계산됩니다. 내일 날짜는 파란색으로 강조하고 `PDD` 로 표시합니다. 매월 1~7일은 `🔥 피크데이` 표시가 붙습니다.
오른쪽 위 **2주 / 한 달** 로 바꿔 볼 수 있습니다. 한 달 보기는 달력(◀ ▶ 로 앞뒤 12개월, 처음엔 PDD가 있는 달)으로 PDD(내일) 칸을 파랗게 `PDD` 표시하고 날마다 내 일정·백업 수를 보여 주고, 날짜를 누르면 그날 일정과 우리 캠프 백업이 아래에 나옵니다.

### 노선관리 (캠프 > 노선코드)

노선관리 메뉴를 처음 열면 DB 시트에 `camps`(캠프), `routes`(노선), `camp_images`(캠프 참고 이미지), `camp_addresses`(상차지 주소), `route_prices`(구분별 단가) 탭이 **자동으로** 생깁니다. (setup 을 다시 실행하지 않아도 됩니다)

1. **캠프 추가**: 오른쪽 위 **+ 캠프 추가** → 캠프명, 캠프 주소, 메모. 캠프명은 겹칠 수 없습니다. 주소 옆 **지도**를 누르면 네이버 지도에서 열립니다.
   - **상차지가 캠프 주소와 다른 곳이면** 같은 창의 **+ 상차지 주소 추가**로 넣습니다. 여러 개 가능하고(최대 10개), 이름(상차지, 2상차지 등)도 바꿀 수 있습니다.
2. **노선 추가**: 캠프를 고르고 **+ 노선 추가** → 노선코드를 줄바꿈·쉼표·띄어쓰기로 여러 개 한꺼번에 붙여 넣을 수 있습니다. 저장 전에 어떻게 나뉘는지, 이미 있는 코드인지 미리 보여 줍니다.
3. **구분1~5는 노선코드에서 자동으로 나뉩니다.**
   - `110ABCD` → 구분1 `110` / 구분2 `A` / 구분3 `B` / 구분4 `C` / 구분5 `D` (앞쪽 숫자 = 구분1, 그 뒤 한 글자씩)
   - 한 구분이 두 글자 이상이면 `110-AB-C-D-E` 처럼 `-` 로 나눠 씁니다.
   - 영문은 자동으로 대문자, 띄어쓰기는 지워집니다. 같은 캠프 안에서는 같은 노선코드를 두 번 쓸 수 없습니다 (다른 캠프는 가능).
4. **노선 찾기·고르기**: 노선 표 위의 구분1~5, 사용여부 칸으로 거르고, 왼쪽 검색창에 노선코드를 넣으면 그 노선이 있는 캠프를 찾아 줍니다.
5. **노선 수정**: 노선 줄을 누르면 노선코드, 캠프(다른 캠프로 옮기기), 사용/중지, 메모를 고칠 수 있습니다. 체크박스로 여러 개를 골라 한꺼번에 사용·중지·삭제할 수도 있습니다. 당분간 안 쓰는 노선은 삭제보다 **중지**를 권장합니다 (나중에 배차·정산 기록이 남아 있어야 하므로).
6. **구분별 단가**: 노선 표 위의 **구분별 단가** 탭. 캠프 노선에서 숫자(구분1)별로 구분2~5의 글자가 자동으로 나열되고, 구분 옆에 **원청단가 · 기사단가 · 백업단가 · 품앗이단가 · 외부단가** 순서로 입력합니다. (기사가 잠시 다른 단가로 일하는 **일시단가**는 정산관리 → 일시단가에서 기사 + 기간으로 넣습니다)
   - 단가는 **숫자 + 구분 + 글자**마다 따로 정합니다. 예: `110ABCD` 는 110의 구분2 `A`, 구분3 `B`, 구분4 `C`, 구분5 `D` 단가를 씁니다. 110의 A 와 111의 A 는 따로입니다.
   - 위쪽에서 숫자·구분·글자로 거를 수 있습니다.
   - 칸을 여러 개 고친 뒤 **단가 저장**을 한 번 누르면 됩니다. Enter 를 누르면 아래 칸으로 넘어갑니다. 한 줄의 단가를 모두 지우고 저장하면 그 줄은 지워집니다.
   - 노선을 누르면 수정 창에서 그 노선의 구분2~5 단가를 한눈에 볼 수 있습니다.
   - 단가 저장 기록은 `admin_log` 에 남습니다.
   - 실제 배차·정산에서 구분2~5 단가 중 어느 것을 쓸지(합산/가장 자세한 구분 등)는 배차·정산 단계에서 정합니다.
7. **참고 이미지**: **+ 이미지 추가** → 여러 장을 고르고 장마다 설명을 적어 올립니다. 사진은 자동으로 줄여서 올립니다. 이미지를 누르면 크게 보고, 설명 고치기, 순서 바꾸기(앞으로/뒤로), 삭제를 할 수 있습니다. 파일은 드라이브 `러너 올인원 데이터/캠프 참고 이미지` 폴더에 저장됩니다.
8. **캠프 삭제**는 그 캠프에 노선이 하나도 없을 때만 됩니다 (참고 이미지·상차지 주소·단가는 같이 지워짐).

### 데이터 초기화 (메뉴별)

기사 정보관리 · 기사스케줄 · 노선관리 · 업무스케줄 · 배번호 관리 화면 오른쪽 위의 **데이터 초기화** (빨간 글씨).

1. 누르면 무엇이 지워지는지 목록이 나옵니다.
2. 확인 칸에 **`모조리 없앤다`** 를 그대로 입력해야 **초기화** 버튼이 눌립니다 (서버에서도 한 번 더 확인).
3. 지우기 전에 해당 시트를 구글 드라이브 **`러너 올인원 데이터 / 초기화 백업`** 폴더에 새 파일로 복사해 둡니다. 완료 화면의 **초기화 백업 파일 열기** 로 바로 볼 수 있고, 잘못 지웠으면 그 파일에서 복사해 원래 시트에 붙여 넣으면 됩니다.
4. 누가 언제 무엇을 지웠는지 `admin_log` 에 백업 파일 주소와 함께 남습니다.

| 메뉴 | 지워지는 것 | 남는 것 |
| --- | --- | --- |
| 기사 정보관리 | 모든 기사, 기사 앱 로그인, 가입 서류 폴더(드라이브 휴지통) | 관리자 로그인, 스케줄·배번호 기록 |
| 기사스케줄 | 스케줄 DB 의 모든 날짜 기록, 비고 줄(빈 비고 줄 3개 다시 만듦) | 기사 정보, 기사별 스케줄 설정 |
| 노선관리 | 캠프·노선·상차지 주소·구분별 단가·참고 이미지(사진은 드라이브 휴지통), 기사의 소속캠프 칸 | 기사 정보, 스케줄 기록 |
| 업무스케줄 | 모든 메모 | — |
| 배번호 관리 | 모든 신청서 | 회사 정보 |

- 시트의 머리글(1행)·드롭다운·서식은 그대로 두고 데이터 줄만 비웁니다. 초기화 후 바로 새로 입력할 수 있습니다.
- 드라이브 휴지통으로 옮긴 파일은 30일 안에 드라이브에서 복구할 수 있습니다.

### 계정관리 (다른 프로그램·서비스 계정)

관리자 화면 **계정관리** 메뉴. 쿠팡 어드민·팀즈·메일·홈택스·은행 등 회사가 쓰는 다른 서비스의 아이디·비밀번호를 모아 둡니다 (기사 계정 아님).

- **+ 새 계정** → 분류, 서비스명, 캠프(캠프별 계정일 때), 아이디, 비밀번호(직접 입력 또는 **자동 생성** 14자), 사용자·담당자, 접속 주소, 메모, 상태(사용/중지).
- **분류 편집**: 분류 추가, 이름 바꾸기(그 분류의 계정도 함께 바뀜), ↑↓ 순서(= 탭 순서), 삭제(그 분류의 계정은 고른 분류로 옮김, 기본 '기타'). 분류 목록은 `account_categories` 탭에 저장되며 시트에서 직접 고쳐도 됩니다. 계정을 저장할 때 새 분류 이름을 쓰면 목록에 자동으로 추가됩니다.
- 목록에서 아이디 **복사**, 비밀번호 **보기**(20초 뒤 자동으로 가림)·**복사**, 접속 주소 **열기 ↗**. 분류 탭·캠프·검색으로 찾기.
- 비밀번호는 암호화해 숨김 칸에만 저장하고, 시트의 `비밀번호` 칸에는 `●●●●●●●●`만 보입니다. 수정할 때 비밀번호 칸을 비워 두면 그대로 유지됩니다.
- 비밀번호 보기·복사·변경, 계정 등록·삭제는 모두 관리자 기록(`admin_log`)에 남습니다 (비밀번호 자체는 기록하지 않음).
- 시트(`accounts` 탭)에서 직접 줄을 추가해도 됩니다. `비밀번호` 칸에 입력하면 자동 암호화되고 ●로 바뀝니다. 다만 직접 입력한 원래 값은 시트 **버전 기록**에 남으므로, 비밀번호는 관리자 화면에서 입력하세요.

### 공지사항

관리자 화면 **공지사항** 메뉴에서 기사 앱에 보일 공지를 올립니다.

- **+ 새 공지** → 제목·내용, **중요**(맨 위 고정 + 기사님이 처음 볼 때 팝업 한 번), **보낼 대상**(전체 기사 / 캠프 선택), 게시 기간(비우면 바로·계속), 상태(게시/숨김).
- 목록 탭: 게시 중 / 예약(시작일 전) / 종료(종료일 지남) / 숨김. 줄을 누르면 수정·삭제. 잠시 내릴 때는 삭제 대신 **숨김**.
- 기사 앱 홈 맨 위에 **📢 공지사항** 카드(최근 3개)가 보이고, 안 읽은 공지는 `N`·`새 글 n` 표시. **전체 보기**에서 눌러 펼쳐 읽습니다. 읽음 표시는 기사님 휴대폰에 저장됩니다.
- 캠프를 고르면 기사 정보의 **배정 캠프**가 그 캠프인 기사에게만 보입니다 (배정 캠프가 없는 기사는 '전체' 공지만 봄).
- 시트(`notices` 탭)에서 직접 줄을 추가해도 됩니다: 제목·내용만 쓰면 공지ID·작성일시·상태(게시)가 자동으로 채워지고, 기사 앱에 바로 반영됩니다. `중요` 칸에 Y, `대상 캠프` 칸에 `강서1, 서초1` 처럼.
- 등록·삭제는 관리자 기록(`admin_log`)에 남습니다.

### 품앗이 (기사 앱 · 기사끼리 용차 일감 주고받기)

바로일 '용차' 방식을 그대로 옮겼습니다. 수수료 없이 기사님끼리 일감을 맡기고 대신 뜁니다.

- **흐름**: 기사가 일감을 올림 → 다른 기사가 **지원하기** (한마디 남기기) → 올린 기사가 **품앗이 관리**에서 지원자에게 📞 전화 → **협의 중** → **배차 확정** → 정산은 두 분이 직접.
- **상태**: 모집 중 / 배차 협의중(초록) / 배차 확정(회색) / 모집 마감 / 취소, 배차일이 지난 확정 일감은 **완료**. 목록 카드에 상태가 겹쳐 보입니다.
- **목록 카드**: 배차일·입차시간, 구분(품앗이☀️ 주간 / 품앗이🌙 야간 · 일택은 숨김), 배송지, 센터·라우트, 평균 물량, 탑 종류, 건당 단가(VAT포함), 지급방법(⭐당일지급 / 주급 / 월급 / 협의), **내용 보기**.
- **필터**: '지원 가능 오더만 보기'(모집 중·오늘 이후·내 일감 아님·아직 지원 안 함·그날 지원 2번 미만) + 배송지·센터 검색.
- **상세**: 위 항목 + 상세 설명. **배송지코드·연락처·첨부 이미지**('배차 확정 기사에게만' 칸)는 올린 기사와 확정된 기사에게만 보입니다. 확정되면 서로의 전화번호가 보입니다.
- **지원 규칙**: 화물운송 종사자격증 서류가 등록된 기사만, 같은 배차일에 2번까지, 내 일감에는 지원 불가.
- **올리기**: 센터를 고르면 노선관리의 라우트 목록이 나오고, 라우트를 고르면 노선관리 **품앗이단가**(없으면 기사단가)가 단가 칸에 제안됩니다. 상세 설명에는 배송 정보·특이사항·정산 정보 틀이 미리 채워집니다.
- **마이페이지**: 품앗이 일감 올리기, 품앗이 관리(지원자 보기·확정·거절·확정 풀기·마감·취소), 지원한 품앗이, 완료한 품앗이(맡긴 것·뛴 것), 내 정보(보기 전용), 비밀번호 변경, 로그아웃.
- **내 스케줄**: 그날 품앗이가 🤝 줄로 보입니다 — **수행**(내가 대신 뛰는 일), **맡김**(내가 올린 일감, 모집 중·협의 중일 때만 — 배차가 확정되면 빠짐). 내가 올린 일감이 배차 확정되고 그날 내 스케줄 칸의 캠프·라우트와 같으면(예: 칸 `527AB`, 일감 `강서1 527B`) 그 칸 아래 **✅ 배차확정 완료 · 대신 뛰는 기사**가 표시되고, 한 달 보기 칸에는 `✅ 확정완료`, **지원**(지원·협의 중). 누르면 일감 상세로 갑니다. 한 달 보기 칸에도 🤝 표시.
- **어드민 기사스케줄 연동**:
  - 배차가 확정되면 대신 뛰는 기사가 **비고 줄 바로 위 '품앗이' 줄**(이름·아이디)에 들어가고, 그날 칸에 `강서1 527B` 처럼 캠프·라우트가 자동으로 적힙니다. 다른 칸처럼 직접 고칠 수 있고, 확정이 풀리거나 취소되면 자동으로 지워집니다.
  - 일을 맡긴 기사의 그날 칸이 일감과 캠프·라우트가 같으면 칸 아래에 초록색 **품앗이 → 대신 뛰는 기사**가 표시됩니다 (칸 글자는 그대로).
  - 스케줄 DB 에는 행ID `PM` + 기사ID, 구분 `품앗이` 줄로 저장됩니다. 품앗이 줄은 미입차·중복 계산과 업로드 테이블에는 넣지 않습니다.
- **데이터**: `pumasi_jobs`(일감 1개 = 1줄), `pumasi_apps`(지원 1건 = 1줄) 탭. 시트에서 상태·단가 등을 직접 고쳐도 바로 반영됩니다. 첨부 이미지는 `품앗이 첨부` 폴더.
- **알림**: 새 지원·지원 취소(올린 기사에게), 협의 중·배차 확정·미선정·확정 취소·모집 마감·일감 취소·내용 변경(지원한 기사에게).
  - **앱 안 알림**: 앱을 열어 둔 동안 30초마다 확인해 화면 위에 알림을 띄우고 진동. 홈 **마이페이지** 타일에 빨간 숫자, **마이페이지 → 🔔 알림**에서 최근 30일 알림(누르면 그 일감으로). 알림은 `pumasi_alerts` 탭에 쌓이고 60일 지나면 새벽에 지워집니다.
  - **휴대폰 푸시** (앱을 닫아도): 기사가 **마이페이지 → 📲 휴대폰 알림 받기**를 켜면 그 기기가 `push_tokens` 탭에 등록됩니다. 아이폰은 홈 화면에 설치한 앱(iOS 16.4 이상)에서만, 안드로이드는 크롬·삼성인터넷에서 됩니다. 처음 한 번 아래 **휴대폰 푸시 준비**가 필요합니다.

#### 휴대폰 푸시 준비 (한 번만, 무료)

1. https://console.firebase.google.com → **프로젝트 추가** → 이름(예: runner-push) → 애널리틱스는 꺼도 됩니다.
2. 프로젝트 화면에서 **웹 앱 추가(`</>`)** → 닉네임 `러너` → **앱 등록**. 나오는 `firebaseConfig` 의 값(apiKey, authDomain, projectId, messagingSenderId, appId)을 적어 둡니다.
3. ⚙️ **프로젝트 설정 → 클라우드 메시징** → 아래 **웹 푸시 인증서 → 키 쌍 생성** → 나온 키를 적어 둡니다 (vapidKey).
4. ⚙️ **프로젝트 설정 → 서비스 계정** → **새 비공개 키 생성** → JSON 파일이 내려받아집니다.
5. Apps Script 편집기 → ⚙️ **프로젝트 설정 → 스크립트 속성** 에 두 개 추가:
   - `FCM_WEB` = (runner-push 프로젝트는 코드에 이미 들어 있어 넣지 않아도 됩니다. 다른 프로젝트일 때만) `{"apiKey":"…","authDomain":"…","projectId":"…","messagingSenderId":"…","appId":"…","vapidKey":"3번 키"}`
     (파이어베이스 화면의 `const firebaseConfig = { … };` 를 그대로 붙여 넣어도 됩니다. 그때는 3번 키를 스크립트 속성 `FCM_VAPID` 로 따로 넣으세요)
   - `FCM_SA` = 4번 JSON 파일 내용 전체를 그대로 붙여 넣기
6. 편집기에서 `Pumasi.gs` → 함수 `pmPushSetupCheck` 고르고 **▶ 실행** → 권한 허용(외부 서비스 연결). 실행 로그에 `푸시 준비 완료` 가 나오면 끝.
   - 서비스 계정 키(FCM_SA)는 비밀번호와 같습니다. 다른 곳에 올리거나 보내지 마세요.


## 시트에서 직접 고치기

`러너 올인원 DB` 의 시트를 그대로 고치면 됩니다. 고치는 즉시 앱에 반영됩니다.

| 하고 싶은 일 | 시트에서 할 일 |
| --- | --- |
| 가입 승인 / 반려 / 사용 중지 | `drivers` 의 **상태** 칸을 `승인` · `반려` · `정지` 로 변경 (승인 시 승인일시 자동 기록) |
| 이름·주소·차량·은행 등 수정 | 해당 칸을 그냥 고침 |
| 주민등록번호 · 운전면허번호 · 계좌번호 수정 | 칸에 **새 번호를 그대로 입력** → 자동으로 암호화되고 `900101-1******` 처럼 가린 번호로 바뀜 (주민번호를 고치면 생년월일도 자동 갱신) |
| 기사 비밀번호 바꿔주기 | **비밀번호 재설정** 칸(주황색 머리글)에 임시 비밀번호 입력 → 바로 적용되고 칸은 비워짐. 기사는 다음 로그인 때 새 비밀번호를 직접 정함 (아래 참고) |
| 기사를 직접 등록 | 빈 줄에 이름(또는 쿠팡플렉스 아이디) 등을 입력 → 기사ID·가입일시·상태(승인대기) 자동 입력. 비밀번호는 위 방법으로 지정 |
| 검색 | 기사 정보관리 검색은 상태·구분 탭과 관계없이 전체 기사에서 찾습니다. 한글은 글자가 완성된 뒤 결과가 바뀝니다 (조합 중 화면을 다시 그리지 않음) |
| 관리자 비밀번호 변경 | 관리자 화면 왼쪽 아래 **비밀번호 변경** → 현재 비밀번호 + 새 비밀번호. 다른 PC·휴대폰의 관리자 로그인은 해제되고 지금 화면은 계속 사용. 관리자 기록에 남음 (비밀번호를 잊었으면 admins 시트의 비밀번호 재설정 칸) |
| 기사ID가 겹쳤을 때 | 기사ID는 겹치지 않게 자동으로 만들어집니다(여러 줄을 한 번에 붙여넣어도 안전). 예전에 겹친 기사ID가 있으면 **기사 정보관리를 열 때 자동으로 고칩니다**: 위쪽(먼저 있던) 줄은 그대로, 아래쪽 줄에 새 ID를 주고, 스케줄 DB 행ID·배번호 신청도 이름으로 맞춰 옮깁니다. 겹친 ID로 열린 로그인은 해제되며(다시 로그인하면 됨), 관리자 기록에 `기사ID 중복 정리` 로 남습니다 |
| 기사구분·기사코드 | `drivers` 의 **기사구분**(고정/백업/품앗이/외부용차, `용차`·`고정기사` 처럼 써도 정리됨), **기사코드** 칸. 같은 기사코드가 있으면 칸에 메모로 알려 줌 |
| 특정 기기 강제 로그아웃 | `sessions` 시트의 **만료일시** 를 지금보다 이전 시각으로 변경 |
| 캠프 추가·이름 바꾸기 | `camps` 빈 줄에 캠프명 입력 → 캠프ID 자동. 캠프명을 바꾸면 `routes`·`camp_images` 의 캠프명 칸도 자동으로 바뀜 |
| 상차지 주소 추가 | `camp_addresses` 빈 줄에 캠프명, 이름(비우면 상차지), 주소 입력 |
| 구분별 단가 입력 | `route_prices` 빈 줄에 캠프명, 숫자(구분1, 예: `110`), 구분(`구분3` 또는 `3`), 글자(예: `B`), 단가들 입력 → 단가ID 자동. 금액은 `1,200원` 처럼 써도 숫자로 정리됨 |
| 스케줄 고치기 | **`러너 올인원 스케줄 DB`** 파일의 `schedule` 탭에서 기사 줄 × 날짜 칸을 그냥 고침 (1행 날짜와 A열 행ID는 바꾸지 말 것). 캠프·이름·기본노선 칸은 기사 정보·노선관리를 따라 자동으로 맞춰짐 |
| 스케줄 시트에 기사 줄 추가 | 빈 줄에 **이름**만 (같은 이름이 여럿이면 **캠프**도) 쓰면 기사 정보에서 찾아 행ID·구분·캠프(노선관리 캠프명)·기본노선이 자동으로 채워짐. 못 찾거나 이미 그 기사 줄이 있으면 칸 메모로 알려 줌. 구분에 `비고`라고 쓰고 이름을 쓰면 새 비고 줄 |
| 기사 스케줄 속성 | `drivers` 의 **소속캠프**(캠프명), **기본노선**, **고정휴무일**, **추가휴무**, **근무형태**, **스케줄 메모**, **스케줄 순서** 칸 |
| 노선 추가 | `routes` 빈 줄에 **캠프명**과 **노선코드**만 입력 → 노선ID·캠프ID·구분1~5·사용여부 자동 |
| 노선을 다른 캠프로 옮기기 | `routes` 의 **캠프명** 칸을 다른 캠프명으로 변경 |
| 노선 중지 | `routes` 의 **사용여부** 를 `중지` 로 (`x`, `N` 으로 써도 중지로 바뀜) |
| 캠프 참고 이미지 추가 | `camp_images` 빈 줄에 캠프명, 드라이브 이미지 **링크**, 설명 입력 |
| 내 메모 열 추가, 열 순서 바꾸기 | 자유롭게 가능. 앱은 열 위치가 아니라 **머리글 이름**으로 칸을 찾습니다 |

잘못된 값을 넣으면(예: 면허번호 자릿수 오류) 그 칸에 **메모(빨간 삼각형)** 로 이유가 표시되고 저장되지 않습니다.

### 지켜야 할 것 두 가지

1. **머리글(1행) 이름은 바꾸지 마세요.** 이름이 바뀌면 앱이 그 열을 찾지 못합니다. 실수로 바꿨다면 원래 이름으로 되돌리거나 `setup` 을 다시 실행하세요.
2. **숨겨진 열(…암호화, 해시, 솔트, 중복검사키)은 직접 고치지 마세요.** 이 칸들은 위의 보이는 칸을 고치면 자동으로 갱신됩니다.

### 개인정보 칸이 가려져 보이는 이유

주민등록번호는 법적으로 암호화해서 저장해야 하는 정보입니다(개인정보 보호법 제24조의2). 그래서 시트에는 가린 번호만 보이고, 고칠 때는 새 번호를 입력하면 자동 암호화되는 방식으로 만들었습니다. 원래 번호 전체는 배번호 신청서를 출력할 때 앱이 풀어서 사용합니다.

### 기존 기사 비밀번호 일괄 설정

1. `drivers` 시트에서 첫 기사 줄의 **비밀번호 재설정** 칸에 임시 비밀번호(영문+숫자 8자 이상, 예: `runner2026`)를 입력합니다.
2. 그 칸을 선택하고 칸 오른쪽 아래 작은 네모를 마지막 기사 줄까지 끌어내립니다. 한 번에 100줄 이하를 권장합니다.
3. 잠시 뒤 칸이 모두 비워지고 **비밀번호 변경 필요** 칸에 `Y` 가 채워지면 적용 완료입니다.
4. 기사님께 아이디와 임시 비밀번호를 알려 드립니다.
5. 기사님이 임시 비밀번호로 로그인하면 **새 비밀번호 설정 화면**이 먼저 나옵니다. 바꾸기 전에는 홈 화면으로 넘어가지 않습니다.
6. 기사님이 바꾸면 **비밀번호 변경 필요** 칸이 자동으로 비워집니다. 누가 아직 안 바꿨는지는 이 칸으로 확인합니다.

기사님이 스스로 비밀번호를 찾을 때는 **아이디, 이름, 연락처, 생년월일, 정산 계좌 은행, 계좌번호**가 모두 시트와 맞아야 합니다. 계좌 정보가 비어 있는 기사님은 스스로 찾을 수 없으니, 위 방법으로 관리자가 임시 비밀번호를 지정해 주세요.

임시 비밀번호는 여러 명이 같으므로, 바꾸기 전까지는 다른 사람이 로그인할 수 있습니다. 가능한 빨리 바꾸도록 안내해 주세요.

기사님은 언제든 앱 홈 화면 아래 **비밀번호 변경**에서 직접 바꿀 수 있습니다. 바꾸면 다른 기기의 자동 로그인은 해제됩니다.

### 기존 기사 서류 사진 한꺼번에 올리기

1. 구글 드라이브 `러너 올인원 데이터` → **`서류 올리기`** 폴더를 엽니다. (`러너 올인원 DB` 의 **서류 연결** 탭 B5 칸 링크로도 열 수 있습니다)
2. 서류 파일 이름을 **`기사_서류종류`** 로 바꿔서 이 폴더에 한꺼번에 끌어다 놓습니다.

   | 부분 | 쓸 수 있는 것 | 예 |
   | --- | --- | --- |
   | 기사 | 쿠팡플렉스 아이디 / 연락처 / 기사ID / 이름 (동명이인이 없을 때만) | `kim@flex.com`, `01012345678`, `김기사` |
   | 서류종류 | `자격증` / `면허증` / `사업자` / `자동차` (이 글자가 들어가면 됨) | `면허증`, `사업자등록증`, `자동차등록증` |

   예: `kim@flex.com_면허증.jpg`, `01012345678_자격증.png`, `김기사_사업자.pdf`
   이미지(jpg, png 등)와 PDF 를 올릴 수 있습니다.

3. `러너 올인원 DB` → **서류 연결** 탭 → **② 실행** 옆 체크박스를 누릅니다.
4. 끝나면 체크가 저절로 풀리고, **결과** 칸과 아래 기록표에 파일마다 연결/실패와 이유가 나옵니다.
   - 연결된 파일: 기사별 서류 폴더로 옮겨지고, `drivers` 시트의 서류 칸에 링크가 들어갑니다.
   - 실패한 파일: `서류 올리기` 폴더에 그대로 남습니다. 이름을 고친 뒤 다시 체크하면 됩니다.
   - 이미 서류 링크가 있던 기사는 새 파일 링크로 바뀌고, 예전 파일은 그 기사 폴더에 남습니다.

파일이 아주 많으면 한 번에 4분 30초까지만 처리하고 "한 번 더 체크해 주세요"라고 안내합니다. 다시 체크하면 남은 파일부터 이어서 처리합니다.

## 데이터 구조

- `drivers` 시트: 기사 1명 = 1줄. 날짜·시각은 모두 `2026-11-02 19:00:00` 형식의 글자로 저장되어 그대로 읽고 고칠 수 있습니다.
- `sessions` 시트: 로그인 기록. 매일 새벽 4시에 만료된 기록을 자동 정리합니다.
- `기사 서류` 폴더: 기사별 하위 폴더에 서류 사진 4장. `drivers` 의 `서류_…` 칸에 링크가 있습니다.
- `러너 올인원 스케줄 DB` 파일의 `schedule` 시트 (기사·노선 DB 와 별도 파일): 기사 1줄 × 날짜 1칸 (기존 운영시트 백업 탭과 같은 모양). A~E열 행ID·구분(기사/비고)·캠프·이름·기본노선, F열부터 날짜. 화면은 2주씩만 읽고 고친 칸만 씁니다.
- `camps` / `routes` / `camp_images` / `camp_addresses` / `route_prices` 시트: 캠프 1개·노선 1개·이미지 1장 = 1줄. 노선은 캠프ID로 캠프에 묶이고(캠프명 칸은 보기 편하라고 같이 적어 두는 사본), 구분1~5는 노선코드에서 자동으로 채워집니다.
- `캠프 참고 이미지` 폴더: 노선관리에서 올린 캠프 사진.
- `러너 올인원 정산 DB` 파일 (기사·노선 DB 와 별도): 정산관리의 `stl_…` 탭. 쿠팡 원천은 정산월마다 한 묶음으로 붙어 있어 그 달 줄만 읽습니다. 계산 결과는 5분 캐시, 마감한 달은 고정 결과를 읽습니다.
- `쿠팡 정산서` 폴더: 올린 쿠팡 정산 엑셀 원본.
- `pumasi_jobs` / `pumasi_apps` 시트: 품앗이 일감·지원. 목록은 1분 캐시이고 고치면 바로 비웁니다.
- `pumasi_alerts` / `push_tokens` 시트: 품앗이 알림(기사 1명에게 1건 = 1줄), 휴대폰 알림 받는 기기(1대 = 1줄, 지우면 그 기기로는 안 감).

## 속도를 위해 적용한 것

**정산관리**
- 정산 DB 의 작은 탭(설정·항목·공제·가불·용차·입금·차수이력 등)은 **Sheets API 한 번(batchGet)** 으로 함께 읽고, 탭마다 버전이 붙은 캐시에 둡니다. 고친 탭만 다시 읽습니다. (`appsscript.json` 에 Sheets 고급 서비스가 켜져 있음. 쓸 수 없으면 자동으로 탭마다 읽기로 바뀝니다)
- 쿠팡 원천·분실·마감 결과는 정산월별 시작·끝 줄을 기억해 그 달 줄만 읽고, 읽은 달은 캐시에 둡니다. 새 정산서를 올릴 때만 다시 읽습니다.
- 저장은 쓴 내용을 바로 캐시에 넣어 다시 읽지 않습니다. 입금체크·메모는 그 한 줄만 씁니다. 입금 상태는 계산 결과와 따로 붙여 체크해도 다시 계산하지 않습니다.
- 정산 DB 를 시트에서 손으로 고치면 편집 트리거가 그 탭 캐시만 버립니다 (행 추가·삭제 같은 구조 변경은 정산 캐시 전체). 기사 정보가 바뀌면 계산 결과만 다시 만듭니다. 기사스케줄 출근일은 최대 10분 뒤 반영되며, 바로 보려면 **다시 계산**.
- 화면: 입금체크는 누르는 즉시 바뀌고(실패하면 되돌림), 표·명의자 사업자 정보 저장은 저장 결과를 그대로 받아 다시 불러오지 않습니다.

| 방법 | 효과 |
| --- | --- |
| 시트 전체를 읽지 않고 TextFinder 로 해당 줄만 찾아 읽음 | 기사가 늘어나도 로그인 속도가 거의 그대로 |
| 머리글 위치, 아이디→줄 번호, 로그인 세션, 기사 요약을 캐시에 보관 | 자동 로그인 확인은 대부분 시트를 열지 않고 끝남 |
| 시트를 고치면 해당 캐시만 즉시 삭제 | 캐시를 써도 직접 수정이 바로 반영됨 |
| 서류 사진을 휴대폰에서 미리 압축(최대 1600px JPEG) 후 한 번에 전송 | 업로드 시간 대폭 단축 (원본 5MB → 약 300KB) |
| 중복검사·업로드는 잠금 밖, 최종 저장만 짧게 잠금 | 여러 명이 동시에 가입해도 대기 최소화 |
| 저장된 기사 정보로 홈을 먼저 보여주고 서버 확인은 뒤에서 | 자동 로그인 시 앱이 바로 열리는 체감 |
| 노선 기준 데이터(캠프·노선·이미지 목록)를 한 번에 읽어 캐시, 저장·시트 수정 때만 새로 읽음 | 노선관리 화면과 앞으로 만들 배차·정산 화면이 시트를 매번 열지 않음 |
| 노선 여러 개를 한 번의 쓰기로 추가, 캠프 사진은 동시에 3장씩 나눠 불러옴 | 노선 수백 개 입력, 사진 많은 캠프도 빠르게 표시 |

구글 Apps Script 특성상 서버 호출 1번에 보통 0.5~1.5초가 걸립니다. 위 방법은 호출 횟수와 호출당 작업량을 줄이는 것입니다.

## 보안

**저장 방식**
- 비밀번호: 솔트 + 비밀키(페퍼) + HMAC-SHA256 200회 반복 해시. 앱·관리자 화면으로 정한 비밀번호는 원문이 어디에도 남지 않습니다.
- 주민등록번호·운전면허번호·계좌번호: 암호화(무결성 태그 포함) 후 저장, 시트에는 가린 번호만 보입니다. 주민번호 중복 가입은 별도 검사키로 막습니다.
- 암호화 키·페퍼는 Apps Script **스크립트 속성**에만 있습니다 (시트·깃허브에 없음). 이 프로젝트의 편집 권한은 대표 계정만 갖게 하세요.
- 가입 서류 사진·캠프 사진은 드라이브 개인 폴더에 저장되고, 화면에는 서버를 거쳐서만 보입니다 (공개 링크를 만들지 않음).

**접근 제어**
- 기사 앱·관리자 화면은 로그인 토큰이 있어야 데이터를 받습니다. 토큰은 시트에 해시로만 저장되고 기간이 지나면 만료됩니다.
- 관리자가 주민번호·면허번호·계좌번호 전체를 보거나, 서류를 열거나, 배번호 서류를 출력하면 `admin_log` 에 기록됩니다.
- 기사 앱에는 본인 일정과, 같은 캠프에 들어오는 백업의 **이름·노선**만 보입니다.
- 웹앱 입구(doPost)는 `api_`·`adm_` 함수만 받습니다. `setup`·`ensureColumns`·`linkUploadedDocs`·`testCrypto` 는 스크립트 주인이 편집기에서 실행할 때만 작동합니다.
- 관리자 화면(깃허브 페이지)은 보안 정책(CSP)으로 구글 웹앱 외의 주소로는 데이터를 보낼 수 없습니다.

**무차별 시도 방지**
- 로그인 10회 실패 시 15분 잠금, 비밀번호 찾기 본인확인 5회 실패 시 30분 잠금, 가입 신청은 전체 1시간 30건까지.

**꼭 지켜 주세요**
- `러너 올인원 데이터` 폴더와 DB 시트는 필요한 관리자에게만 공유하세요. 시트를 볼 수 있는 사람은 이름·연락처·주소·생년월일을 볼 수 있습니다. "링크가 있는 모든 사용자" 공유는 쓰지 마세요.
- 주민번호·면허번호·계좌번호·비밀번호를 **시트 칸에 직접 입력하면 원래 값이 구글 시트 '버전 기록'에 남습니다.** 이런 값은 관리자 화면(기사 정보 → 수정 / 임시 비밀번호)에서 입력하세요.
- `초기화 백업` 폴더의 복사본에도 개인정보가 들어 있습니다. 필요 없어진 복사본은 지워 주세요.
